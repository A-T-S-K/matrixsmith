# Source-scoped micro:bit LED Matrix State reference

This is a reusable offline compiler reference, not accepted MatrixSmith hardware
support. No device, Bluetooth session, readback, write or acceptance evidence is
created. The driver always declares dry-run-only, even when passed a live context.
It is absent from built-in live discovery and has no probes or notifications.

## Binary contract and consequences

The service is `e95dd91d-251d-470a-a062-fa1922dfa9a8`; the matrix characteristic is
`e95d7b77-251d-470a-a062-fa1922dfa9a8`. The encoder requires exactly 25 binary
samples in a 5×5 row-major grid; the driver requires exact black/white RGB.
Shape, count and values are validated before allocation proportional to input.
One five-byte binary value is planned with-response from the pinned WRITE
property. It is not text, regardless of the documentation's “utf8 octets” wording.
There is no header, compression, CRC, padding, stored program or chunk protocol.

Rows are top to bottom with USB at the top and edge connector at the bottom.
Each row maps left to right to bits 4, 3, 2, 1, 0. Bits 7–5 are zero on output.
The pinned callback tests only bits 4–0 and accepts lengths 1–5, potentially
leaving later rows untouched. This compiler deliberately accepts full matrices
only. A future supplied-byte decoder must preserve unexplained high input bits
and label output as decoded supplied bytes; none is included in this slice.

The pinned matrix-write path calls `stopAnimation()` then updates image pixels
to 255 or 0. It can interrupt an animation. No storage call occurs in that path;
this is a source consequence, not evidence of physical acceptance or power-cycle
behavior. Power-cycle behavior, other firmware, timing and rendering remain
unknown. No actual receipt or TX timestamp is fabricated.

Service inclusion depends on firmware. The constructor uses configured security
requirements; MakeCode describes pairing. This tool establishes neither pairing
nor security compatibility. Names and UUIDs supply candidate explanations only,
not generation authentication or proof the service is available on a board.

## Independent proof

Literal vectors in tests cover blank (`00 00 00 00 00`), full
(`1F 1F 1F 1F 1F`), asymmetric (`10 01 08 04 12`) and all 25 individual pixels.
Expected octets are written independently rather than generated by the encoder.
Every single-pixel row uses the explicit sequence `10 08 04 02 01`, matching
the documentation and the pinned callback's `4-x` bit test. Malformed RGB and
binary buffers, operations and references reject. No native text, controls,
decoder, installation or live execution is supported.
