# Local declarative profiles

Profile Document V1 is separate from Diagnostic Bundle V3. The published
`public/profile-v1.schema.json` is strict: unknown fields fail closed. Parsing
bounds UTF-8 bytes (16 KiB), depth (8), tokens (512) and encoded string length
(2048) before JSON parsing or proportional validation. Structure then limits
arrays, identifiers, strings and dimensions. The build generates a standalone
validator; no browser schema compiler, dynamic evaluation or dependency fetch is
used.

`coolledux-reviewed-v1` is an application adapter contract, not an engine hash:
FFF0/FFF1, existing CoolLEDUX codecs, widths divisible by eight, dimensions up to
128, byte brightness, and the `coolledux-source-v1` template. That template fixes
source defaults in reviewed code. It does not generalize the eight-column tile,
16-row stride, channel mapping, claim interpretation or consequence ceilings.
Future incompatible adapter semantics require a new reference and review.

Local documents contribute matching predicates, contradictions, geometry,
labels, limitations and author citations. They cannot declare physical evidence,
verified assurance, trusted scope, callbacks, opcodes or quirks. Missing GATT
access or manufacturer data is not a contradiction. Present conflicting
geometry, manufacturer fields or required properties withdraw the exact profile.

The reusable built-in JSON excludes specimen identifiers and capture blobs. The
existing historical profile evidence module and research retain those records.
Physical iLedHat templates attach only to the frozen application-owned definition;
copied IDs, metadata or labels cannot attach them. Local definitions always receive
source-only evidence, experimental capabilities and no iLedHat guided tests.
The authored 48×8 fixture now uses the same declarative adapter as local documents.
This is a software extension proof; eight-row firmware rendering is unverified.

Driver and profile duplicate IDs fail registration. Local namespace `matrixsmith`
and the built-in iLedHat ID are reserved. Runtime namespaces `provisional` and
`protocol-candidate` are also reserved: their `provisional:` geometry and
`protocol-candidate:` probe-plan identity prefixes belong to the application.
These reservations are compatibility checks shared by review and direct
acceptance; structurally valid documents remain parseable for inspection.
Duplicate local identity/revision and
matching-name collisions fail; there is no silent replacement. Registries copy
and freeze their list and implementation facade, accepted documents and profile
snapshots are deeply frozen. Plans receive the accepted document digest and
explicit adapter reference in application-owned provenance protected by the
existing transmission digest. Unversioned injected machinery is explicitly
unversioned; no engine hash is invented.

Home provides one local-file entry and a focused review showing identity,
compatibility, matching, contradictions, geometry, parameters, provenance and
limitations before loading. A malformed or incompatible file preserves the
previous registry/workspace, drafts and any pending valid profile review; the
rejected attempt reports its problems or error without replacing that review.
The prepared immutable registry is published only
when a fresh runtime can be constructed. Active or retained connections block
loading; disconnect first. Drafts stay with their existing UI owners. Replacing
the runtime drops current evidence, confirmations and prepared work. Exported
local profiles can be reviewed and loaded in a fresh browser session. There is
no durable installation storage or automatic restoration across restarts.

Accepted definition identity includes the document and resolved profile/template
snapshot. Application preparation writes it into digest-covered provenance;
a definition mismatch rejects stale prepared work. This identifies accepted
software definitions, not newly established hardware support.

## Reusable still candidates (Profile Document V2)

V1 remains source-only and unchanged. V2 is a separate strict published contract
(`public/profile-v2.schema.json`); older V1 readers reject its document version and
candidate fields. Both versions use the same 16 KiB bounded parsing and generated
standalone validation. Unknown versions and executable/authority fields fail
closed. Diagnostic Bundle V3 is unchanged.

After current live CoolLEDUX identification and explicit geometry, **Create
candidate profile** captures an inspectable proposal. The only configuration is
the registered `coolledux-reviewed-v1` implementation, RGB444, 16-row stride,
eight-column tiles, and width 16–64 divisible by eight. Raw-channel observations
are separate from actual encoder verification; unsupported permutations cannot
be imported as executable parameters. A completed candidate recommends
`animation-single-frame`; an incomplete candidate omits that recommendation.
The application builder requires valid target/definition-bound attempts and the
existing static viability evaluator, rather than transfer acceptance, completed
labels or saved summaries. Generation/export installs nothing and changes no
claims, strategy, drafts or confirmation.

`candidate.history` is historical provenance, never approval. Its definition
identity records the software definition used for those observations. Reloaded
configuration receives a new accepted definition digest covering the candidate;
these identities need not coincide. `evidenceDigest` refers to a separate existing
privacy-projected V3 attachment using a canonical content digest. This digest is
an integrity/reference check, not a signature or authenticity claim. An absent
attachment leaves the profile inspectable. Inspection rejects conflicting content,
geometry or definition references and installs no historical claims.

Company ID may be null; a company field is included only when actually accessible
and is a contradiction condition, never an inferred manufacturer. Manufacturer,
firmware, model and chip identity remain unknown. Name and shared GATT describe
candidate matching conditions and do not establish family or physical-unit
identity. Public labels, local ID and the observed Bluetooth matching name are
editable before export. The matching name may be personal or identifying: this
profile is not universally identifier-free. The separate shareable evidence
projection removes specimen/session identifiers, including legacy `details.target`
and current `physicalDeviceKey`, while preserving existing test, attempt,
transaction, definition and timing relationships. Full local archives remain a
separate explicit report option with original provenance.

Copy/download use owner-supervised file ports. Invalid edits and export failures
preserve the prior valid candidate and allow retry. A changed target, connection,
geometry, definition, evidence or replacement review disables stale export and
suppresses late success. Loaded-profile export uses the same supervised action.
Attempt validity, measured timing and transfer provenance participate in the
private review binding as well as generation checks. Generation also validates
and reinterprets the retained observations, compares their metrics with the
derived claims, and checks measured durations against the retained timeline.
Changed or incomplete observations cannot reuse previously successful claims
to describe a completed candidate. The supervised export
validates the exact formatted profile or evidence bytes against reload bounds
before calling file/clipboard ports; an oversized formatted export preserves
the accepted source and reports an error.

Reload uses the existing atomic local installation path, creates a disconnected
runtime and never connects or sends automatically. Identity/matching collisions
remain errors; use a fresh browser session to replace a loaded definition. Local
namespaces cannot take built-in or runtime identities. Matching alone cannot
identify a V2 candidate's family. Eligible live family identification must happen
again; an accessible contradictory reported size withdraws candidate matching.
Repeat the existing three steps: still bootstrap with measured 15-second hold,
raw channels/black, then encoder. Historical/imported/reconnected observations
cannot satisfy current authority. Only fresh successful verification enables
experimental text/images. Experimental permission, static viability and exact
persistent-send consequence confirmation remain in force. Other content and
routine support are not added.

The durable installation is the exported file. Loading is browser-session-only;
there is no persistent catalog, ZIP package, signing, submission or promotion to
accepted shipping support. Simulator/browser tests prove software behavior, not
physical hardware acceptance.
