# CoolLEDUX source provenance

MatrixSmith's TypeScript implementation was written independently from protocol facts and conformance vectors. Python source was not copied or mechanically translated.

## Primary source

- Repository: `CharlesLennon/coolledux-ble`
- Commit: `4f5656d9882adb4926c9dff4dc3fa5783b40a7ac`
- License: MIT
- Consulted: `PROTOCOL.md`, `coolledux/wire.py`, `coolledux/commands.py`, `coolledux/ble.py`, `README.md`, and `LICENSE`
- Facts used: FFF0/FFF1, write without response, notifications on FFF1, shared envelope/escaping, brightness `0x04`, power `0x05`, mirror `0x0C`, device info `0x1F`, and the documented distinction between newer CoolLEDUX and older CoolLEDX.

The source reports hardware testing on another CoolLEDUX sign and a roughly 30-byte device-info response. The exact iLedHat returned 48 bytes, so MatrixSmith parses a confirmed prefix and preserves the remainder rather than imposing the source device's length.

## Stored-program protocol facts used

From `PROTOCOL.md`, `coolledux/wire.py`, `coolledux/colors.py`, and `coolledux/content.py` (all at the pinned commit):

- Custom CRC-32: poly `0x04C11DB7`, init `0xFFFFFFFF`, MSB-first, no final complement.
- Okumura LZSS with N=512, F=18, THRESHOLD=2; the safe/all-literal variant is the hardware-reliable choice for multi-color raw-pixel frames over write-without-response.
- Program container: 8 zero bytes, content-number byte, zero byte, per-segment data. Announce cmd `0x02` (CRC, uncompressed length, index, count, show count); data cmd `0x03` chunks of 128 bytes with reserved byte, total compressed size, chunk index, chunk length, data, XOR checksum. Everything in the shared `0x01…0x03` escaped envelope.
- Two distinct RGB444 encodings: plain /16 truncation for text color runs; a clamping transfer curve (≤47→0, ≥238→15, linear ramp between) for per-pixel Graffiti/Animation content.
- Off sentinels: Graffiti renders literal `0x0000` as bright white, so the off color is `0x0004` (dimmest escape-free nonzero value); the Animation path renders `0x0000` as genuine black.
- Graffiti segments require mode 0 (Static) for per-pixel color, carry an inner 4-byte pixel-stream length, and cap at ~8 rendered columns per segment; the fix is tiling ≤8-column segments (full physical height) inside one program with content-number = tile count.
- Animation segments use the two-byte content tag `0x03 0x01`, a frame count, a per-frame u16 millisecond delay list, and loop forever on-device after one upload.
- Native GIF segments (cmd `0x0C`) carry literal .gif bytes; hardware-confirmed upstream only in the untiled ≤8-column zone.
- Decorative Frame border (cmd `0x04`) addresses perimeter LEDs from a color table and does not hit the segment cap.
- Pacing: ~60 ms between packet writes, owned by the sender, not the codec.

## Conformance cross-check

Golden vectors in `tests/fixtures/coolledux/conformance.json` were generated by executing the pinned Python checkout in a temporary directory outside the repository (CRC vectors, LZSS regular/safe streams, envelope escaping, announce and chunk packets, RGB444 text/pixel encodings for known colors, and complete tiled Graffiti / tiled Animation / GIF / frame-border packet lists for a deterministic 32×16 quadrant image). The MatrixSmith TypeScript implementation matches every vector byte-for-byte, including the regular LZSS compressor, and the MatrixSmith LZSS decoder round-trips both its own and the reference's compressed streams. No unresolved disagreement affects hardware writes.

Differences by design: MatrixSmith derives every content dimension from the `DeviceProfile` (32×16 for the iLedHat) instead of the reference's 64×16 constants, substitutes the Graffiti off sentinel for any pixel whose channels all collapse to 0 through the transfer curve, and performs pacing in the executor from per-packet plan metadata.

## Evidence boundaries

The source documents brightness across raw 0–255. The iLedHat directly verifies `0x40`; `0xCC` was observed in device-info state before the change. Power and mirror remain dry-run-only because external confirmation on another unit does not establish behavior or persistence on this iLedHat.

Password set and OTA remain unimplemented by policy.

## Focused re-inspection (2026-08-31)

A targeted re-read of the pinned commit (`PROTOCOL.md`, `coolledux/content.py`, `coolledux/colors.py`, `coolledux/wire.py`, `coolledux/commands.py`, `coolledux/ble.py`) for the iLedHat characterization phase established, with provenance "documented upstream" unless noted:

- **stayTime**: appears only in the shared segment header layout and as the default `stay_time=3`; no semantics, units, or special values are documented. (Not addressed upstream beyond the layout.)
- **mode**: mode 0 is called Static and "MUST be 0" for per-pixel color; mode 2 renders shape-only white. Other values untested upstream; per-mode movement is not documented.
- **speed**: no unit semantics; upstream notes speed appears irrelevant once mode=0.
- **Upload notifications**: "echoes most commands back, not a reliable per-chunk ack — don't gate retries on it." `send_packets` is fire-and-forget with fixed 60 ms pacing and never subscribes during uploads. No receipt payload format (e.g. `02 00`, `03 00 00 <index> 00`) is documented upstream; MatrixSmith's structural decoding of the physically observed receipts is its own conservative addition.
- **Animation timing**: 16-bit BE milliseconds per frame; firmware loops forever; ceiling 65535 ms per frame; no loop-count primitive.
- **Height stride**: firmware assumes a 16-row stride per segment regardless of declared showHeight (hardware-confirmed upstream).
- **Post-upload latency**: ~16–20 s on-device delay before playback for tens-of-KB programs (upstream observation).
- **Advertisement/colorMode**: nothing upstream about advertisement layout, colorModeRaw, value 3, RGBW, or a white channel; `light_color_mode_bytes` (13 03) is an unrelated cycling-gradient command.
- Upstream protocol origin: reverse-engineered from the decompiled `com.jtkj.led1248` Android app (`CoolledUXUtils`); README links the older-generation `coolledx-driver` PyPI project and the author's `esp32-sign-controller` as the only external references.
